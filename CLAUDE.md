# learning-log

Repositório pessoal de "real problems, real solutions" (ver README.md). Cada arquivo `.md` nas pastas (`k8s/`, `signoz/`, `docker/`, etc.) documenta um problema técnico real e sua resolução.

# Repositórios

Sempre que houver necessidade de consultar este repositório, deve ser realizado um `git pull` na branch `main` antes de realizar qualquer análise ou consulta.

# Portfólio de Problemas (Notion)

Sempre que um novo arquivo de problema/solução for adicionado ou um existente for atualizado com uma resolução confirmada, o mesmo conteúdo deve também ser registrado como um toggle temático na página Notion:
https://app.notion.com/p/cleverson/Portifolio-de-Problemas-2d824176115480da9fe0c67977aaab37

Formato do registro:
- Um toggle temático por problema, com ícone + título descritivo (nunca "issue 1", "issue 2" etc.).
- Dentro dele, três sub-toggles, um por idioma: 🇧🇷 Português (BR), 🇬🇧 English, 🇪🇸 Español.
- Cada sub-toggle traz, em texto simples: `issue:` / `causa raiz:` (`root cause:` / `causa raíz:`) / `solução:` (`solution:` / `solución:`).
- Escrever em voz neutra/passiva (nunca "eu fiz"), pois nem todo problema documentado foi resolvido pelo próprio Cleverson.

Não é necessário que o problema esteja "fechado" formalmente em nenhum lugar (Jira, etc.) para registrar — julgar pelo conteúdo (o arquivo já traz "Resolved as" / seção de solução) se o problema já foi tecnicamente resolvido.

Esta é a mesma regra global definida no CLAUDE.md raiz (`~/CLAUDE.md`) do usuário.
